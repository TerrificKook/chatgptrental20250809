# Наполнение и перенос каталога

Изменения карточек и демо-модерация видны только в текущем браузере. Они не отправляются в GitHub и не меняют каталог у других посетителей.

## Новая карточка

1. Войдите тестовым участником или создайте псевдоним без настоящих контактов.
2. Нажмите «Сдать реквизит». Дополнительный профиль владельца относится к этому же участнику.
3. На первом шаге заполните название, категорию, описание и характеристики. Все данные этой публичной демонстрации должны оставаться вымышленными.
4. На шаге изображений загрузите от 1 до 6 фотографий JPEG, PNG или WebP, не больше 8 МБ каждая. Размеры - от 80 × 80 пикселей, не больше 40 мегапикселей. Проверьте превью, главное фото и порядок. HTML и SVG не принимаются как фото.
5. Укажите цену за календарный день, количество, залог, район, выдачу и упаковку. Сохраните черновик или отправьте карточку на модерацию.
6. Администратор демо публикует карточку или отклоняет с причиной. После исправления возможна повторная отправка. Существенная правка опубликованного объявления возвращает его в очередь.

Архивирование скрывает карточку из каталога и сохраняет старые запросы. Категорию с объявлениями удалить нельзя; сначала нужно переназначить объявления. Название и порядок категорий редактируются администратором.

## Экспорт и локальный импорт

В демонстрационном режиме администратора откройте раздел «Данные».

- JSON переносит поля публичной схемы и ссылки на изображения. Экспорт включает объявления всех статусов, в том числе черновики; причины отклонения и внутренние заметки не включаются.
- ZIP содержит `catalog.json` и реальные изображения, в том числе загруженные в браузере. Для переноса карточек с новыми фото используйте ZIP.
- Экспорт каталога не включает заявки, внутренние заметки и причины отклонения, избранное, сохранённые подборки, полномочия и журнал. Это не полная резервная копия локального состояния.
- Перед импортом проверяются версия, связи владельцев и категорий, ID и slug, денежные значения, количество, статусы и файлы. Неверный пакет не должен менять состояние.
- Пределы импорта: ZIP до 30 МБ, отдельное изображение до 8 МБ, распакованное содержимое до 100 МБ, не более 600 файлов, JSON до 4 МБ. Пути вне разрешённой папки изображений отклоняются.
- Корректный пакет добавляет новые ID и обновляет совпадающие. Остальные записи не удаляются молча.
- Сброс данных - отдельное подтверждаемое действие. Экспортируйте нужный каталог до него.

При передаче ZIP помните, что это обычный доступный получателю файл. Не добавляйте настоящие контакты, персональные данные и приватные материалы.

## Обновление общего seed разработчиком

Команды выполняются из корня репозитория с поддерживаемой версией Node и установленными из lockfile зависимостями:

```sh
npm ci
npm run catalog:import -- /абсолютный/путь/kinostore-catalog.zip --dry-run
npm run catalog:import -- /абсолютный/путь/kinostore-catalog.zip
npm run seed:check
npm run typecheck
npm run lint
npm test
npm run build
```

`--dry-run` проверяет пакет и показывает итог без записи. Обычный импорт сохраняет прежний `public/catalog.json` и затрагиваемые файлы изображений в `backups/<timestamp>`, затем обновляет данные по ID. Не публикуйте служебные backups вместе со сборкой. Отчёт о фактическом запуске этих команд находится в [ACCEPTANCE_REPORT.md](ACCEPTANCE_REPORT.md).

Проверка `seed:check` намеренно фиксирует объём исходного демо: 48 опубликованных вещей, 8 категорий, 8 владельцев и 6 подборок. Если осознанно меняется состав общего демонстрационного набора, обновите эти ожидаемые показатели и отчёт; не отключайте проверку ради зелёной отметки.

Просмотрите изменения, выполните визуальную проверку и сохраняйте в Git только публичные исходники каталога и изображения текущей задачи. Публикация осуществляется из среды разработчика с отдельной веткой и PR; браузер не хранит GitHub-токен и не выполняет push. Выкладка содержит только `dist`.

Уже открывавшийся браузер сохраняет свою локальную версию. Новый seed не должен молча уничтожать локальные данные: для демонстрации обновлённого набора используйте чистый браузерный контекст либо предусмотренный подтверждаемый сброс после экспорта.

## Предел текущей версии

Демо не содержит общую серверную базу и защищённую админку. Импорт и новая сборка подходят для вымышленных материалов текущей проверки. Для реальных владельцев и заявок необходимы работы из [NEXT_PILOT.md](NEXT_PILOT.md).

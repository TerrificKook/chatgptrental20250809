# Kinostore · Catalog Demo v1

Адаптивный интерактивный каталог предметного реквизита. Вещи, цены, характеристики и участники вымышлены. Москва и МО. Рабочее название не означает права на товарный знак.

React + TypeScript + Vite, собственный CSS и SVG, IndexedDB. Настоящей регистрации, сервера, платежей, телефонов и отправки сообщений нет. Это не production-ready приложение. Демонстрационный администратор публично доступен и не заменяет серверную защиту прав.

## Запуск

Node **24.19.0** (см. `.nvmrc`). Обычный npm входит в установку Node.

```sh
npm ci
npm run dev
```

Адрес разработки: `http://127.0.0.1:5173/chatgptrental20250809/`.

```sh
npm run typecheck
npm run lint
npm test
npm run seed:check
npm run build
npx playwright install chromium
npm run test:e2e
```

```sh
npm run preview -- --port 4173
```

Production preview: `http://127.0.0.1:4173/chatgptrental20250809/`. Настоящая публичная публикация и её проверка зафиксированы в `docs/ACCEPTANCE_REPORT.md`; предполагаемый URL не является доказательством работающего деплоя.

## Что можно проверить

- Каталог: 48 исходных опубликованных вещей, 8 категорий, 8 вымышленных владельцев, 6 тематических подборок. Дополнительные черновик, ожидающее и отклонённое объявления.
- Поиск по названию, описанию и тегам, ё/е, категории, цена, район, эпоха, цвет, доставка, владелец; сортировка и фильтры в URL.
- Избранное и подборки отдельно для каждого участника, расчёт календарных дней включительно, разные части запроса для владельцев, снимки цен и условий, ответы по строкам, отмена и завершение.
- Единый кабинет, местные тестовые псевдонимы, трёхшаговое размещение, настоящая загрузка растровых фото и сохранение после обновления страницы.
- Админка: модерация, каталог, владельцы, запросы, категории, журнал, публичный JSON/ZIP, предварительная проверка импорта и подтверждаемый сброс.

Текущий участник виден в панели «Режим демонстрации». Выбор сохраняется для вкладки; общий каталог хранится в IndexedDB и транзакционно обновляется между вкладками. Изменения не отправляются в GitHub и не синхронизируются между устройствами. Очистка данных браузера удаляет локальную историю. Не вносите реальные контакты и заявки.

## Публикация и восстановление

`vite.config.ts` задаёт `/chatgptrental20250809/`. Используется hash-маршрутизация. Прямые адреса карточек переживают обновление страницы. `noindex,nofollow` не делает сайт приватным. Внешние шрифты, CDN и API не нужны.

CI `.github/workflows/verify-and-demo.yml` проверяет PR и рабочую ветку. Деплой выполняется только из `codex/kinostore-catalog-demo`: вручную (`workflow_dispatch`) либо коммитом с маркером `[publish-demo]`, после успешных проверок. Чужие PR не публикуются. Загружается только `dist`; исходники, legacy, screenshots и локальные данные браузера в Pages не входят. Основная ветка не сливается автоматически.

На момент начала задания Pages использовал `main`, `/`, `build_type=legacy`, без `cname`; environment `github-pages` разрешал только `main`. Защита не обходится. Если она блокирует рабочую ветку, владелец должен явно разрешить её в environment перед публикацией. Фактический статус указан в отчёте.

Старая версия сохранена без изменений в `legacy/kinostore_vanilla_index.html` и в исходном файле корня. SHA-256: `6f90199903208ada072fa55dde270981547ffdf96f50f03bf1d515dc78c34561`. Исходный commit: `c945024e862e71ff1fdec217ecef32b7ef25aaac`. Для восстановления достаточно вернуться к старому источнику Pages или отдельно опубликовать сохранённый HTML; не используйте force push и удаление истории.

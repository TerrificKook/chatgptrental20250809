# Архитектура демо

Kinostore - статический React + TypeScript frontend, собранный Vite. Серверной базы, регистрации, API-ключей и фоновой отправки сообщений в этой версии нет. Публичная сборка получает исходный каталог из локальных файлов; изменения хранятся в IndexedDB браузера.

## Слои и файлы

| Слой | Назначение |
| --- | --- |
| `src/domain/models.ts` | Общие типы каталога, профилей, подборки, запросов и журнала |
| `src/domain/service.ts` | Действия участника, проверки владения, жизненный цикл карточек и запросов |
| `src/data/repository.ts` | `IndexedDbRepository`: чтение и атомарное сохранение состояния |
| `src/domain/catalog-package.ts` | Проверка и перенос публичного каталога, изображения и ZIP |
| `public/catalog.json` | Версионированный общий начальный набор, отдельный от React-компонентов |
| `public/images/catalog/` | Локальные каталожные изображения и уменьшенные версии |
| `scripts/catalog-import.ts` | Импорт переносимого пакета в исходники для новой общей сборки |
| `scripts/seed-check.ts` | Проверка количества, связей, заполнения и существования изображений |
| `tests/` | Доменные и браузерные проверки |

## Сущности

- `User` - одна тестовая сущность участника с псевдонимом. Она может арендовать и сдавать. Поле `isAdmin` не выдаётся обычной формой создания профиля.
- `SellerProfile` - публичные условия владельца, связанного с `User` через `userId`.
- `Category`, `Listing`, `ImageAsset`, `Collection` - категории, объявления, изображения и подборки ID. Каталог показывает только `published`.
- `Favorite` - связь участника и интересной вещи. `Selection` - текущая подборка с датами и количеством, привязанная к участнику; `SavedSelection` - её именованная сохранённая версия. При восстановлении проверяются текущие условия и доступность карточек.
- `RequestGroup` - запрос участника с общими датами. `OwnerRequest` - отдельная часть каждого владельца.
- `RequestLineSnapshot` - сохранённые в момент запроса название, количество, ставка, залог, выдача, упаковка и доставка. Изменение или архивирование объявления не переписывает историю запроса.
- `AuditEvent` - локальный журнал автора, действия, объекта, пояснения и времени.

`CatalogPackage` содержит `schemaVersion`, `categories`, `sellers`, `listings`, `images`, `collections`. `CatalogState` расширяет его пользователями, избранным, текущими и сохранёнными подборками, запросами, журналом и ревизией состояния. Каталожный пакет включает объявления всех статусов, в том числе черновики, но не содержит заявки, пользовательские подборки, полномочия, внутренние причины отклонения или журнал. Не считайте черновик приватным материалом при экспорте.

## Правила предметной области

Деньги хранятся целым числом копеек. Оба календарных дня включаются: 1-1 октября - один день, 1-3 октября - три. Аренда равна ставке × дням × количеству; залог равен залогу за единицу × количеству. Залог не увеличивается с длительностью. Количество - положительное целое в пределах количества объявления.

Создание запроса атомарно сохраняет общую группу, части по владельцам и снимки. Ключ повторной отправки предотвращает дубли. Самостоятельная отправка запроса на свою вещь запрещена. Ответ одной части не превращает весь запрос в подтверждённый. Отмена и явное завершение имеют отдельные статусы; запрос не списывает остаток и не гарантирует резерв.

Жизненный цикл объявления: `draft` → `pending` → `published` / `rejected`. Для отклонения обязательна причина; исправленную карточку можно отправить снова. Изменение опубликованной карточки требует новой модерации. `archived` скрывает объявление, сохраняя историю.

## Граница полномочий

Сервис проверяет `actorId`, владение карточкой, адресата заявки и допустимость перехода. Эти проверки нужны для правильного поведения демо. Они не обеспечивают безопасность от владельца браузера: весь JavaScript и демо-переключатель доступны посетителю. В реальном пилоте backend должен повторять проверки независимо от frontend.

Стандартные тестовые акторы: `participant`, `owner-1` ... `owner-8` и `admin`. Новые псевдонимы создают обычных участников. Переключение на `admin` находится только в явно обозначенном демонстрационном инструменте.

## Хранение и публикация

Общий seed имеет версию схемы и применяется при первом открытии именованного хранилища. Перезагрузка страницы использует сохранённое состояние. Изображения пользователя хранятся как бинарные данные в IndexedDB, а не как большие строки localStorage. Локальные blob URL нужны только для отображения, в переносимом пакете им соответствуют реальные файлы.

Отдельные устройства, профили браузера и origin имеют отдельные IndexedDB. Каталог не синхронизируется через GitHub. Для обновления общего демо нужен проверенный экспорт, импорт в исходники, новая сборка и разрешённая публикация `dist`.

Hash-маршруты сохраняют прямые ссылки на GitHub Pages с базовым путём `/chatgptrental20250809/`. `noindex, nofollow` сообщает поисковым роботам назначение демо, но не делает данные приватными.
